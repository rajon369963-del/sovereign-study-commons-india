# Sovereign Hyper-Interconnection Protocol

## Core rule
Prefer verified existing wheels over reinvention, but treat search counts and synthesis counts as targets until receipts prove them.

## Evidence-ranked research loop
1. **Internal wheel first:** check current Rajon/MIGL artifacts that are actually accessible in the runtime.
2. **Mature OSS next:** prefer maintained, license-compatible libraries/apps with reproducible source locators and version/commit evidence.
3. **Practitioner evidence:** use public forums/issues/discussions only when relevant. Record source locator, retrieval date, extracted insight, and confidence. Do not call a target count completed unless all counted items have reviewable evidence.
4. **Cross-domain synthesis:** connect only evidence-bearing atoms. Label hypotheses as `CANDIDATE` or `UNVERIFIED` until tested.
5. **Custom code last:** create only the smallest adapter for a `TRUE_NEW_GAP` after existing wheels and native platform features are ruled out.
6. **Verification:** run the smallest deterministic/adversarial tests appropriate to the effect, then physically read back the destination state.

## Count semantics
- `TARGET_100_COMPETITORS` means a research ceiling/goal, not a completed census.
- `TARGET_100_PRACTITIONER_INSIGHTS` means a search target, not proof that 100 unique high-quality findings exist.
- `TARGET_100_REUSABLE_WHEELS` means a discovery target, not proof that tools were downloaded, installed, licensed, compatible, or integrated.
- Promote a target count to `VERIFIED_N` only from a reviewable manifest with one record per counted item.

## Safety and rights
- Respect licenses, robots/access rules, platform terms, privacy, copyright, and repository permissions.
- Never use account switching or multi-account routing to evade quotas, rate limits, or provider restrictions.
- Public accessibility does not imply redistribution permission.
- Local installation claims remain `LOCAL_ONLY` until physically inventoried in the current runtime.
- Do not mass-post, fabricate community adoption, or buy/solicit stars.

## Completion contract
`PAIN -> EVIDENCE -> EXISTING_WHEEL -> SMALLEST_ADAPTER -> TEST -> PHYSICAL_READBACK -> RECEIPT`

A green test proves only the tested boundary. It does not automatically prove production deployment, provenance, learner value, numerical gains, or causal effectiveness.
